## Opaque, seed-derived ids

`disguised_advertisement`, `false_urgency`, `confirm_shaming`, and `interface_interference` each had one or more ids that encoded the answer to the pattern's task in the id string itself (`item-ad` named the ad, `decline-btn` named the correct exit under a loaded label, etc. — full reasoning in `docs/identifier_audit.md`). Their replacement ids are generated by `testbed/src/lib/ids.ts:assignOpaqueIds(seed, n, prefix)`: a deterministic seed-keyed shuffle over a fixed pool of content-free hex-like tokens (`OPAQUE_TOKENS`), so the same seed always reproduces the same id (episodes stay comparable at a given seed) but different seeds assign differently (the id string itself never becomes a second, fixed encoding of the role, and neither does its position — DOM order for a given role is still controlled by the pattern's own intensity logic, unaffected by this).

Episodes run under `matrix-full-e1e2` (and any run predating 2026-08-22) used the old literal ids and are **not comparable** to anything run after this change for these four patterns — see `docs/decisions.md` 2026-08-22.
